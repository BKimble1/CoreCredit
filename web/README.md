# corecredit.idlery.com

The public website: one marketing home page, the three support and legal pages App Review
opens, and a 404. It is static HTML with no script, no web font, no external request, no
cookie, no analytics and no tracker — the Privacy Policy it links to promises exactly that, so
the site making the promise has to keep it.

Hosted on Netlify. `web/corecredit-netlify.zip` is the deployable bundle; deploying is a manual
drag-and-drop, and nothing in this repository pushes to the host.

## Layout

| Path | What it is |
| --- | --- |
| `web/src/index.html` | the home page — **source of truth, edit here** |
| `web/src/404.html` | the not-found page |
| `web/src/assets/` | images, generated (see below) — do not hand-edit |
| `web/src/_redirects` | `/support`, `/privacy`, `/terms` → their `.html` files |
| `web/src/_headers` | CSP and the cache policy for `assets/` |
| `web/src/robots.txt`, `web/src/sitemap.xml` | the usual two |
| `web/tools/build_assets.py` | derives `assets/` from the app captures at the repository root |
| `web/tools/build_site.py` | assembles `web/dist/` and writes the ZIP |
| `web/tools/preview_site.py` | serves `web/dist/` like Netlify and photographs it |
| `web/corecredit-netlify.zip` | **the artifact to deploy** (committed) |
| `web/dist/` | the unpacked bundle (git-ignored, rebuilt on demand) |

`support.html`, `privacy.html` and `terms.html` are **not** here. They are generated by
`docs/tools/render_legal_pages.py` into `docs/legal-public/` from the JSON the app reads on
device, so the published wording and the on-device wording cannot drift; `build_site.py` copies
them into the bundle. Editing them by hand fails `scripts/verify_repository.py`.

## Rebuilding

```sh
python3 web/tools/build_assets.py    # only after changing a capture at the repository root
python3 web/tools/build_site.py      # always — writes web/dist/ and web/corecredit-netlify.zip
python3 web/tools/preview_site.py    # optional — screenshots at phone, tablet and desktop widths
```

`build_site.py` refuses to write a bundle that loads anything from another origin, that carries a
script or an iframe, that links to a file it does not contain, or whose App Store links are not
the exact listing URL. The ZIP is written with a fixed timestamp, so an unchanged site rebuilds
to a byte-identical file and a changed ZIP in a diff means the site actually changed.

`preview_site.py` fails on horizontal overflow, an image that did not load, an image without an
`alt`, an image not shown at its own aspect ratio, a console error or a failed request. It needs
`pip install playwright` and a Chromium on the machine.

## Deploying

The ZIP holds `index.html` at its root with no enclosing folder, which is what Netlify's
drag-and-drop deploy expects. Unzip it and drop the *contents* on the existing site's **Deploys**
tab, or drop the ZIP itself. The custom domain, DNS and HTTPS settings belong to the site, not to
the deploy, so replacing the files never changes the address.

## Images

Every picture is a real capture of the shipping app or the shipping app icon. `build_assets.py`
reads the captures committed at the repository root, crops the status bar rather than rewriting
it, and writes WebP for the screenshots and PNG for the icon and the social preview. No image on
this site depicts a screen the app does not have.
